# Exact Fertility Growing Zones 1.0.2

RimWorld 1.6の標準の農業ゾーンツールに、肥沃度が一致するマスだけを選ぶフィルターを追加します。日本語と英語に対応しています。

## 導入

1. Steam Workshopなどから **Harmony**（Workshop ID：2009463077）を導入します。
2. ZIPを展開し、`ExactFertilityGrowingZones`フォルダーをRimWorldの`Mods`フォルダーへコピーします。展開済みの同名フォルダーを直接コピーしても導入できます。
3. `RimWorld/Mods/ExactFertilityGrowingZones/About/About.xml`と`Assemblies/ExactFertilityGrowingZones.dll`が存在することを確認します。フォルダーを二重に入れないでください。
4. ゲームのMod一覧でHarmonyと本Modを有効にします。HarmonyをCoreより前、本ModをCoreより後に配置し、ゲームを再起動します。

導入用ZIPは[GitHub Releases](https://github.com/KotaLow/RimWorld-Exact-Fertility-Growing-Zones/releases/latest)から取得できます。GitHubの自動生成される「Source code」ではなく、`ExactFertilityGrowingZones-1.0.2-RimWorld1.6.zip`をダウンロードしてください。

### 試作版・旧版からの更新

ゲームを終了し、このZIPの`ExactFertilityGrowingZones`フォルダーを既存の同名フォルダーへ上書きしてから起動してください。旧版と新版を別々のModとして同時に入れないでください。

1.0.2では、公開向けに作者表記・パッケージIDを公開GitHub名へ統一し、環境固有のビルドパスを除去しました。試作版とはパッケージIDが異なるため、Mod一覧で有効になっていることを確認してください。古いセーブを開く際にMod構成の差異が表示される場合がありますが、独自のゾーン型やセーブ項目は追加していません。肥沃度フィルターの動作は1.0.1と同じです。

### 1.0.1の変更

広い範囲をドラッグすると、肥沃度が一致しないマスごとに、毎フレーム同じ数値整形とメッセージ翻訳を繰り返していました。1.0.1では、このメッセージを肥沃度・言語・数値書式が変わるまで再利用し、大量の一時文字列の生成を取り除きます。

キャッシュするのは表示用メッセージだけです。マスの肥沃度や設置可否は保存せず毎回判定するため、地形や汚染、建物の変化は従来どおり反映されます。通常の設置不可判定とその理由も維持します。

## 使い方

1. 「アーキテクト」→「ゾーン」から通常の農業ゾーンツールを選びます。
2. 追加表示される「肥沃度：100%」ボタンを押します。
3. 探索済みのマスから取得した候補（例：70%、100%、140%）から、対象の肥沃度を選びます。選択すると「肥沃度で絞る」がオンになります。
4. 通常どおり範囲をドラッグします。一致するマスだけがプレビューと作成の対象になります。
5. 通常の指定に戻すには「肥沃度で絞る」をオフにします。既存ゾーンの拡張時も同じフィルターを使用できます。

起動時のフィルターはオフ、初期選択値は100%です。選択状態は同じゲーム起動中は他のマップやコロニーでも共有され、ゲームを終了するとリセットされます。候補は一覧を開くたびに再取得するため、探索や地形の変化も反映されます。正の肥沃度が見つからない場合は、選択不可の案内を表示します。

候補に表示されても、標準ルールで農業ゾーンを設置できないマスには設置しません。肥沃度以外の設置条件、他の種類のゾーン、既存ゾーン内のマスは変更しません。候補が離れた場所に分かれている場合のゾーン分割も、ゲーム標準の処理に従います。

## 互換性と削除

独自のゾーン型やセーブ項目は追加しません。作成結果は通常の農業ゾーンです。Modを外しても、そのゾーンを通常のゾーンとして扱える設計です。ただし、Mod追加・削除を伴う実際のセーブ再読込試験は未実施です。

ゲーム標準の設置判定が許可したマスに対し、`FertilityGrid.FertilityAt`の値と指定値の差が0.00001以下かを確認します。ドラッグ中の判定と実際の指定で、標準の`CanDesignateCell`を共用します。肥沃度や農業ゾーンツールを大きく変更する他Modとの組み合わせは未検証です。

## ビルド方法

Windows、.NET SDK、.NET Framework 4.7.2 Developer Packを用意します。RimWorld 1.6とHarmonyのDLLをローカルから参照します。

配布ZIP内のこのフォルダーから実行する場合：

```powershell
dotnet build .\Source\ExactFertilityGrowingZones.csproj -c Release '-p:RimWorldPath=C:\Games\RimWorld' '-p:HarmonyPath=C:\Mods\Harmony\1.6\Assemblies\0Harmony.dll'
```

パスは例です。自分の環境に合わせて変更してください。`RIMWORLD_PATH`と`HARMONY_DLL_PATH`環境変数でも指定できます。成果物は`Assemblies/ExactFertilityGrowingZones.dll`です。ソースリポジトリのルートにはZIPを再作成できる`build.ps1`と自動検証用の`tests`・`tools`もあります。ゲーム本体やUnity、HarmonyのDLLは再配布しません。

## 検証状況

2026年11月3日、ローカルのRimWorld **1.6.4871 rev590**で使用されるDLLを参照しました。

- Releaseビルド：成功、警告0・エラー0。
- 肥沃度の一致・不一致、許容誤差の境界、候補の並び順・重複排除、空候補、無効値、追加地形の小数値と表示、メッセージ再利用・対象値／言語／数値書式変更時の更新など：自動テスト22項目に合格。
- 実際のゲームDLLに対する、設置判定と追加GUIのHarmonyパッチ適用：合格。
- フィルター無効時の標準の許可判定、および有効時の標準の拒否判定・拒否理由の維持：自動テストに合格。
- .NET 10上の文字列整形のみの比較テスト（ウォームアップ後、同じ肥沃度の不一致メッセージ25万回）：旧処理は73.02ms／34,000,000バイトの割り当て、キャッシュ利用時は0.66ms／0バイト。ゲームの翻訳処理・描画・通常の設置判定を含まず、**実ゲームのFPS向上率を示す測定ではありません**。
- 1.0.0はユーザーの実ゲームで基本機能の動作確認済みです。広い範囲をドラッグするとFPSが低下するとの報告を受け、上記の改善を行いました。
- **1.0.1以降の実ゲームでのFPS比較は未実施**。細かな操作ケースとMod追加・削除後のセーブ再読込も自動検証の対象には含まれません。

ゲーム内確認では、旧版でFPSが低下した同じセーブ・同じ視点・同じ一時停止状態で同じ範囲をドラッグし、更新前後を比較してください。砂利・土・肥えた土が混ざる範囲で100%を選び、土だけが指定されることも確認できます。ゲーム標準の広範囲プレビュー自体にも負荷があるため、本変更ですべての描画負荷がなくなるわけではありません。
